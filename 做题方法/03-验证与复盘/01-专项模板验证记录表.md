## 二、模块级验收

- [ ] 每个专项至少有标准题验证。
- [ ] 每个专项至少有一个边界变式。
- [ ] 重要定理均检查前提。
- [ ] 同一题型的不同方法比较过适用边界。
- [ ] 跨模板调用路径清楚。
- [ ] 例题答案经过独立复算。
- [ ] 真题年份、题号与来源可追溯。
- [ ] 修订后回读 GitHub 文件确认内容。

## 三、缺陷分类

| 编号 | 缺陷类型 | 典型表现 | 修订要求 |
|---|---|---|---|
| E1 | 数学错误 | 公式、结论或计算错误 | 立即修正并复算 |
| E2 | 条件遗漏 | 定理前提不完整 | 补前提和反例 |
| E3 | 路线错误 | 方法适用范围判断错误 | 重写触发条件 |
| E4 | 步骤跳跃 | 学生无法照做 | 拆成可执行动作 |
| E5 | 重复冲突 | 多文件重复或说法不一致 | 指定主模板并交叉引用 |
| E6 | 例题覆盖不足 | 只有简单标准题 | 增加变式和综合题 |
| E7 | 格式问题 | LaTeX、目录或链接错误 | 统一格式并回读 |

## 四、升级状态
初稿 → 数学复核 → 变式验证 → 真题验证 → 模块交叉验收 → 定稿。

任何一步发现错误，都回到相应步骤修订，不允许跳过验证直接标记定稿。
